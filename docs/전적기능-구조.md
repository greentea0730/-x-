# 전적 기능 구조 및 동작 명세

## 1. 개요

전적 기능은 Eternal Return Open API에서 유저의 시즌 랭크 통계와 게임 기록을 조회한 뒤, 하나의 메인 Embed와 최대 5개의 상세 Embed로 Discord에 출력한다.

핵심 원칙은 게임 기록 API를 기능별로 중복 호출하지 않는 것이다. 게임 기록을 한 번 수집한 뒤 동일한 목록을 최근 7일 그래프, 최근 20게임 순위, 최근 5게임 상세 출력에서 공유한다.

```text
Discord 메시지
  -> 닉네임/UID 확인
  -> 시즌 통계 조회
  -> 게임 기록 페이지 조회
  -> 공통 UserGame 목록 생성
       -> 최근 7일 RP 그래프
       -> 최근 20게임 순위
       -> 최근 5게임 상세 Embed
```

## 2. 주요 구현 위치

| 파일 | 책임 |
| --- | --- |
| `MainProgram.cs` | Discord 명령 처리, 조회 흐름 조정, Embed 전송 |
| `Services/ERApiServices.cs` | Eternal Return API 호출, 페이지네이션, 데이터 가공 |
| `Services/ERDataModels.cs` | API 응답 및 출력용 모델 정의 |
| `Services/UserRegistrationService.cs` | Discord 사용자별 닉네임, UID, 상세 출력 설정 저장 |
| `assets/characters/` | 최근 게임 캐릭터 이미지 |

## 3. 사용자 입력 경로

지원되는 전적 조회 입력은 다음과 같다.

- `!전적 닉네임`
- `!전적` — 등록된 닉네임 사용
- 지정 채널에서 닉네임만 입력
- 지정 채널에서 `.` 또는 `!` 입력

`!전적 닉네임`은 먼저 닉네임을 UID로 변환한다. `!전적`은 `UserRegistrationService`에 저장된 UID를 사용하므로 닉네임 검색 API를 다시 호출하지 않는다.

## 4. API 호출 순서

### 4.1 닉네임으로 UID 조회

```text
GET /v1/user/nickname?query={nickname}
```

응답의 `user.userId`를 이후 요청에 사용한다.

### 4.2 시즌 랭크 통계 조회

```text
GET /v2/user/stats/uid/{uid}/{seasonId}/3
```

현재 구현은 시즌 ID `41`, 랭크 모드 `3`을 사용한다.

통계에서 사용하는 값:

- MMR 및 티어
- 순위와 랭크 백분위
- 전체 게임 수와 승리 수
- Top 3 비율
- 캐릭터별 게임 수와 승리 수

랭크 게임 기록이 없으면 게임 기록 조회 없이 안내 메시지를 출력한다.

### 4.3 게임 기록 조회

```text
GET /v1/user/games/uid/{uid}
GET /v1/user/games/uid/{uid}?next={next}
```

`next` 커서가 있으면 다음 페이지를 요청한다. 현재 최대 100페이지까지 조회할 수 있다.

조회 종료 조건:

1. 랭크 게임을 20개 이상 확보하고 7일 전 날짜까지 도달한 경우
2. API가 다음 페이지를 반환하지 않는 경우
3. 빈 페이지가 반환된 경우
4. API 오류가 재시도 후에도 지속되는 경우
5. 최대 100페이지에 도달한 경우

페이지에서 현재 시즌이 아닌 기록은 제외한다. 따라서 하루에 많은 게임을 플레이한 유저도 최근 7일 경계까지 도달할 수 있도록 20게임 확보만으로 조기 종료하지 않는다.

## 5. 공통 데이터 재사용

전적 조회의 핵심 흐름은 다음과 같다.

```csharp
var recentGames = await _erApiService.GetRecentGamesAsync(userId);

var graph = _erApiService.GetWeeklyRankPointGraph(recentGames);
var rankSummary = _erApiService.GetRecentRankSummary(recentGames);
var details = _erApiService.GetRecentGameDetails(recentGames);
```

`recentGames`는 하나의 API 조회 결과이며, 세 출력 기능이 이 목록을 공유한다. 따라서 그래프와 최근 전적을 만들기 위해 동일한 게임 기록을 반복 요청하지 않는다.

## 6. 메인 전적 Embed

메인 Embed에는 다음 정보가 포함된다.

- 현재 티어
- 현재 점수와 순위 백분위
- 다음 티어까지 필요한 점수
- 전체 게임 수, 승률, Top 3 비율
- 모스트 캐릭터 5개
- 최근 7일 RP 그래프
- 최근 20게임 순위
- 최근 5게임 상세 설정 안내 문구

최근 5게임 상세 출력이 비활성화되어도 메인 Embed의 최근 20게임 순위는 계속 표시된다.

## 7. 최근 7일 RP 그래프

처리 방식:

1. 랭크 모드 게임만 선택한다.
2. 현재 시즌 게임만 선택한다.
3. 게임을 시작 날짜별로 그룹화한다.
4. 하루에 여러 게임이 있으면 가장 최근 게임의 RP를 사용한다.
5. 최근 플레이 날짜 기준 최대 7일을 사용한다.
6. 극단적인 점수는 그래프 표시값에 한해 완화한다.
7. 그래프 최소 범위를 500 RP로 보장한다.
8. 결과를 Discord 코드블록으로 변환한다.

원본 게임 데이터나 실제 RP 값은 변경하지 않는다. 이상치 보정은 그래프의 가독성만을 위한 표시 계층의 처리다.

## 8. 최근 20게임 순위

랭크 게임을 시작 시간 내림차순으로 정렬한 뒤 최대 20개를 사용한다. 10개씩 두 줄로 나누어 메인 Embed에 출력한다.

| 상태 | 표시 |
| --- | --- |
| 1위 | 🥇 |
| 2위 | 🥈 |
| 3위 | 🥉 |
| 탈출 | 🚪 |
| 그 외 순위 | 순위 숫자 |
| 순위 없음 | — |

20게임 미만인 유저는 실제로 존재하는 게임만 출력한다.

## 9. 최근 5게임 상세 Embed

최신 랭크 게임 최대 5개를 각각 별도 Embed로 전송한다. 캐릭터 이미지가 있으면 파일 첨부와 함께 썸네일로 표시한다.

표시 항목:

- 순위 또는 탈출
- 캐릭터명
- 시작 시각
- 경기 지속 시간
- TK, K, A
- DMG, VIS, H

코드블록 내부 형식:

```text
4위 · 셀린       9월 6일 11시 11분 · 18:24
TK /  K  /  A            DMG / VIS /  H
 6 /  4 /   0          14661 / 19 / 76
```

Embed 색상:

- 1위: 밝은 연두색
- 2위: 파란색
- 3위: 하늘색
- 탈출: 남색
- 그 외: 회색

Discord Embed의 레이아웃 제약상 캐릭터 이미지는 왼쪽 대형 이미지가 아니라 썸네일 영역에 표시된다.

## 10. 상세 기록 출력 설정

`!루미 설정`으로 사용자별 최근 5게임 상세 Embed 출력 여부를 변경할 수 있다.

동작:

1. 현재 활성화 상태면 끌지 묻는다.
2. 현재 비활성화 상태면 켤지 묻는다.
3. 다음 메시지가 `ㅇㅇ`이면 상태를 반전한다.
4. `ㄴㄴ` 또는 다른 메시지면 설정을 취소한다.

설정은 `user-registrations.json`에 Discord 사용자 ID별로 저장된다. 신규 사용자의 기본값은 활성화다.

출력 결과:

```text
활성화   -> 메인 Embed + 최근 게임 상세 Embed 최대 5개
비활성화 -> 메인 Embed만 출력
```

설정 확인을 기다리는 동안 해당 사용자의 다음 메시지는 일반 명령으로 처리하지 않고 설정 응답으로 소비한다.

## 11. 장애 및 예외 처리

- 닉네임을 찾지 못하면 UID 조회 단계에서 종료한다.
- 랭크 통계가 없으면 랭크 게임 없음 메시지를 출력한다.
- API 오류는 제한된 횟수만 재시도한다.
- 게임 기록이 20개 미만이면 확보된 기록만 사용한다.
- 최근 게임 상세를 만들 수 없으면 메인 전적 Embed는 계속 출력한다.
- 캐릭터 이미지 파일이 없으면 이미지 없이 상세 Embed를 출력한다.

## 12. 유지보수 시 주의사항

- 게임 기록 API를 새 기능에서 직접 다시 호출하지 말고 `recentGames` 재사용을 우선한다.
- 최근 범위나 페이지 종료 조건을 변경할 때 API 호출량과 429 응답 가능성을 함께 검토한다.
- `MatchingMode == 3`은 현재 랭크 모드 필터이므로 모드 정책 변경 시 관련 가공 함수 전체를 확인해야 한다.
- `UserGame` 필드를 추가할 때 `ERDataModels.cs`, 데이터 가공 함수, Embed 출력부를 함께 수정한다.
- 캐릭터 코드와 이미지 파일 매핑 순서를 변경하면 최근 게임 썸네일이 잘못 표시될 수 있다.
